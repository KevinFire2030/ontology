데이터베이스가 준비되었으니 이제 Python 환경과 LLM API를 연결합니다. 이 책은 특정 프레임워크에 기대지 않습니다. 필요한 것은 데이터베이스 드라이버, 임베딩·채팅 API 클라이언트, 그리고 설정 파일을 읽는 도구 정도입니다. 얇게 유지한 이유는 독자가 자기 프레임워크로 옮기기 쉽게 하기 위해서입니다.

가상 환경과 패키지 설치

.env는 .gitignore에 들어 있어 커밋되지 않습니다. API 키를 코드나 노트북에 직접 적지 마세요. 이 책의 코드는 키를 오직 환경변수에서만 읽습니다.

모델 선택에 대해 한마디 덧붙입니다. 이 책에 실린 정답률·토큰·시간 수치는 모두 gpt-5.6-luna로 측정했습니다. 더 큰 모델을 쓰면 기본 RAG의 정답률이 올라갈 수 있지만, 이 책의 관심은 "같은 모델에서 구성을 바꾸면 무엇이 달라지는가"이므로 모델은 처음부터 끝까지 고정했습니다. 그래서 예제 저장소의 기본값도 같은 모델로 두었습니다. 독자가 다른 모델을 쓰면 절대 수치는 달라지고 경향은 대체로 유지됩니다. 어떤 모델로 쟀는지는 08-1의 재현 기록 표에도 적어 두었습니다.

모델에 따라 API가 받는 인자도 다릅니다. temperature를 받지 않는 모델이 있어서, 공통 모듈은 temperature를 넣어 호출했다가 거부되면 빼고 다시 호출하고 그 사실을 기억합니다. 이 책의 실측도 temperature를 넘기지 않은 상태로 이뤄졌습니다.

다른 LLM 공급자로 바꾸기

OpenAI 호환 API를 제공하는 공급자라면 OPENAI_BASE_URL과 모델 이름만 바꾸면 됩니다. 사내 프록시, Azure OpenAI, 로컬 추론 서버(vLLM, Ollama의 OpenAI 호환 모드 등)가 여기에 해당합니다.

주의할 점은 임베딩 차원입니다. text-embedding-3-small은 1536차원이고, 다른 임베딩 모델은 차원이 다릅니다. EMBEDDING_DIM을 모델에 맞게 바꾸지 않으면 테이블 생성 시 vector(1536) 컬럼과 맞지 않아 삽입이 실패합니다. 차원을 바꾼 뒤에는 인덱스를 다시 만들어야 합니다.

호환 API가 아닌 공급자(예: 다른 SDK를 써야 하는 경우)는 common/llm.py의 chat()과 embed() 두 함수만 바꾸면 됩니다. 나머지 코드는 이 두 함수만 호출합니다.

공통 LLM 모듈

common/llm.py는 세 가지 일을 합니다. 모델과 온도를 고정하고, 호출 횟수·토큰·시간을 누적하고, JSON 응답을 받는 편의 함수를 제공합니다.

# common/llm.py 발췌
LLM_MODEL = os.environ.get("LLM_MODEL", "gpt-5.6-luna")
EMBEDDING_MODEL = os.environ.get("EMBEDDING_MODEL", "text-embedding-3-small")
EMBEDDING_DIM = int(os.environ.get("EMBEDDING_DIM", "1536"))

def chat(system: str, user: str, *, json_mode: bool = False, temperature: float = 0.0) -> str:
    t = time.time()
    kwargs = {}
    if json_mode:
        kwargs["response_format"] = {"type": "json_object"}
    resp = client().chat.completions.create(
        model=LLM_MODEL,
        temperature=temperature,
        messages=[{"role": "system", "content": system}, {"role": "user", "content": user}],
        **kwargs,
    )
    usage.calls += 1
    usage.prompt_tokens += resp.usage.prompt_tokens
    usage.completion_tokens += resp.usage.completion_tokens
    usage.seconds += time.time() - t
    return resp.choices[0].message.content or ""

온도를 0으로 고정한 것은 재현성 때문입니다. 완전히 같은 답이 보장되지는 않지만 실행 간 편차가 줄어듭니다. 토큰과 시간을 누적하는 usage 객체는 8-6에서 구성별 비용을 비교할 때 씁니다.
