03-1. PostgreSQL + pgvector 설치 (Docker Compose)

[검증] 두 경로 모두 실측 · 내장 경로는 PostgreSQL 16.2 + pgvector 0.6.2 (Windows) · Docker 경로는 Ubuntu 22.04 / Docker 28.4.0에서 실행 검수 완료(2026-09-08)

이 책의 모든 실습은 PostgreSQL 하나로 진행합니다. 벡터 검색에는 pgvector 확장을, 9장의 그래프 비교에는 재귀 CTE와 Apache AGE 확장을 씁니다. 그래서 설치할 것은 확장이 포함된 PostgreSQL 한 대뿐입니다. 이 절에서는 두 가지 설치 경로를 안내합니다. Docker가 있으면 Docker Compose로, 없으면 Python 패키지로 내장 PostgreSQL을 띄웁니다.

경로 1: Docker Compose

예제 저장소 루트의 docker-compose.yml은 다음과 같습니다.

services:
  # 1~8장·11장 실습용: pgvector 포함 (AGE 없음)
  db:
    image: pgvector/pgvector:pg16
    container_name: ontology-db
    environment:
      POSTGRES_USER: ontology
      POSTGRES_PASSWORD: ontology
      POSTGRES_DB: ontology
    ports:
      - "5432:5432"
    volumes:
      - pgdata:/var/lib/postgresql/data

  # 09-2의 Apache AGE 절에서만 사용: AGE 포함 (pgvector 없음)
  age:
    image: apache/age:release_PG16_1.6.0
    container_name: ontology-age
    environment:
      POSTGRES_USER: ontology
      POSTGRES_PASSWORD: ontology
      POSTGRES_DB: ontology
    ports:
      - "5433:5432"
    volumes:
      - agedata:/var/lib/postgresql/data

volumes:
  pgdata:
  agedata:

컨테이너를 두 개 띄우는 이유가 있습니다. 하나의 이미지로 pgvector와 AGE를 함께 쓸 수 없기 때문입니다. 두 공식 이미지를 직접 띄워 확장 목록을 확인한 결과는 다음과 같습니다.

이미지 PostgreSQL 사용 가능한 확장
pgvector/pgvector:pg16 16.15 vector 0.8.6 (age 없음)
apache/age:release_PG16_1.6.0 16.10 age 1.6.0 (vector 없음)

apache/age 이미지에서 확장을 만들어 보면 이렇게 실패합니다.

ERROR:  extension "vector" is not available
DETAIL:  Could not open extension control file
         "/usr/share/postgresql/16/extension/vector.control": No such file or directory.

확장 파일이 이미지 안에 먼저 들어 있어야 CREATE EXTENSION이 동작하므로, 컨테이너에서 SQL만으로 pgvector를 추가할 수는 없습니다. 그래서 이 책은 벡터 검색이 필요한 대부분의 실습을 pgvector 컨테이너(db, 5432)에서 하고, 09-2의 Cypher 절만 AGE 컨테이너(age, 5433)에서 합니다. 두 확장이 한 데이터베이스 안에 모두 필요하면 apache/age 이미지를 기반으로 pgvector를 빌드해 넣은 사용자 정의 이미지를 만들어야 합니다.

태그 이름에 주의하십시오. apache/age의 태그는 release_PG16_1.6.0처럼 PostgreSQL 메이저 버전과 AGE 버전을 함께 적는 규칙입니다. PG16_latest 같은 이름은 존재하지 않아 pull이 실패합니다. 이미지 구성과 태그는 바뀔 수 있으니 https://hub.docker.com/r/apache/age 와 https://hub.docker.com/r/pgvector/pgvector 에서 현재 태그를 확인해 주세요.

내장 경로의 pgvector는 0.6.2이고 Docker 이미지의 pgvector는 0.8.6입니다. 이 책의 실습에서 쓰는 기능(vector 타입, 거리 연산자, ivfflat 인덱스)은 두 버전에서 모두 동작합니다.

실행은 한 줄입니다.

docker compose up -d

이후 접속 문자열은 다음과 같고, 예제 저장소의 .env 파일에 그대로 들어갑니다.

DATABASE_URL=postgresql://ontology:ontology@localhost:5432/ontology

09-2의 AGE 절만 5433 포트를 씁니다.

AGE_DATABASE_URL=postgresql://ontology:ontology@localhost:5433/ontology

경로 2: Docker 없이 내장 PostgreSQL

집필 환경에는 Docker가 없어서 이 경로로 모든 실측을 진행했습니다. pgserver라는 Python 패키지가 PostgreSQL 16과 pgvector 확장을 함께 담고 있어, 설치만 하면 별도 설정 없이 데이터베이스가 뜹니다.

python -m pip install pgserver

예제 저장소의 공통 모듈은 .env의 DATABASE_URL이 비어 있으면 자동으로 이 경로를 씁니다. 저장소 안 pgdata 폴더에 데이터가 저장되고, 처음 실행할 때 초기화(initdb)가 한 번 일어납니다.

# common/db.py 발췌
def database_url() -> str:
    url = os.environ.get("DATABASE_URL", "").strip()
    if url:
        return url
    global _embedded
    if _embedded is None:
        import pgserver  # 내장 PostgreSQL (Docker 없는 환경용)
        _embedded = pgserver.get_server(str(ROOT / "pgdata"))
    return _embedded.get_uri()

실측 결과입니다. 처음 기동은 초기화 때문에 10초 남짓 걸리고, 두 번째부터는 1~2초입니다.

uri: postgresql://postgres:@127.0.0.1:5270/postgres
startup sec: 11.3
PostgreSQL 16.2 on x86_64-pc-mingw64, compiled by gcc.exe (x86_64-posix-seh-rev2, Built by MinGW-W64 project) 12.2.0, 64-bit
available ext: [('vector', '0.6.2')]
vector ext: ('0.6.2',)
(1.0,)

마지막 줄은 벡터 거리 계산이 동작하는지 확인한 것입니다. 벡터 [1,2,3]과 [1,2,4]의 유클리드 거리 1.0이 나왔습니다.

내장 경로의 제약이 하나 있습니다. Apache AGE 확장이 없습니다. 위 출력에서 사용 가능한 확장이 vector 하나뿐인 것이 그 증거입니다. 그래서 9장의 AGE 절은 위 Docker 경로의 age 컨테이너에서 실측했고, 재귀 CTE로 그래프를 다루는 부분은 두 경로 모두에서 실측했습니다.

포트가 기동마다 달라질 수 있다는 점도 알아 두세요. 위 출력의 5270은 임의로 배정된 포트입니다. 코드에서는 항상 get_uri()로 받은 주소를 쓰고, 직접 psql로 붙을 때만 출력된 주소를 복사합니다.

확장 확인

어느 경로든 접속한 뒤 확장을 확인합니다. Python에서 확인하면 다음과 같습니다.

import psycopg
conn = psycopg.connect("postgresql://ontology:ontology@localhost:5432/ontology")
print(conn.execute(
    "select name, default_version from pg_available_extensions "
    "where name in ('vector','age') order by 1").fetchall())
conn.execute("create extension if not exists vector")
conn.commit()
확장 용도 없을 때
vector 임베딩 저장과 유사도 검색 (모든 장) pgvector를 별도 설치. Docker라면 pgvector/pgvector:pg16 이미지로 바꾸고 AGE를 포기하는 선택도 가능
age Cypher 질의 (9-2, 9-3 일부) 재귀 CTE로 대체 가능. 책의 결론에는 영향 없음

공통 모듈의 connect() 함수는 접속할 때마다 vector 확장을 활성화하므로, 독자가 직접 create extension을 실행할 일은 없습니다.

자주 막히는 지점

포트 5432가 이미 사용 중. 로컬에 다른 PostgreSQL이 있으면 Docker 컨테이너가 뜨지 못합니다. docker-compose.yml의 포트를 "5433:5432"로 바꾸고 DATABASE_URL의 포트도 맞춥니다.

Windows에서 pgserver 초기화 실패. 저장소 경로에 한글이 들어 있으면 initdb가 실패합니다. 한국어 Windows의 기본 인코딩(cp949)으로 경로를 읽다가 디코딩 오류가 나기 때문입니다. 검수 과정에서 한글 경로에 저장소를 두고 실행해 이 오류를 재현했고, 저장소를 영문 경로로 복사한 뒤 다시 실행해 정상 기동을 확인했습니다. 저장소는 한글이 없는 경로에 두시기 바랍니다.

pgdata 폴더를 지우고 싶을 때. 내장 경로는 저장소 안 pgdata 폴더가 데이터베이스 전부입니다. 실습을 처음부터 다시 하려면 이 폴더를 지우면 됩니다. 지우기 전에 프로세스가 종료되었는지 확인하세요. Docker 경로는 볼륨을 지웁니다.

docker compose down -v

정리

  • 설치할 것은 확장이 포함된 PostgreSQL 한 대이며, Docker Compose 또는 pgserver 패키지 중 하나를 고릅니다.
  • 내장 경로는 PostgreSQL 16.2 + pgvector 0.6.2로 실측했고 AGE만 없습니다.
  • 공통 모듈이 두 경로를 자동으로 구분하므로 이후 코드는 경로에 관계없이 같습니다.
